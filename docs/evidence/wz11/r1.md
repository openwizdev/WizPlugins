# R1 correction round 1

The first review at `4241e74` found that closing the last settings consumer
cleared an outstanding save lock. A reopened page could send a second write
before the first response, allowing responses to replace newer preferences.

The registered settings section is now exercised alone with the same plugin ID
and host snapshot across reopening. Four cases cover success and rejection,
with reopening before settlement or after settlement while no consumers remain.
The previous preview fixture kept other consumers mounted and missed this path.

The new proof failed in three cases before the fix. Both reopen-before-settlement
cases exposed enabled controls, and the unmounted successful settlement exposed
a stale acknowledgement on reopening. The unmounted rejection case already
passed. The red proof and its output were committed at `54aaf61` before the fix.

Cleanup now retains a pending request and its lock. Settlement publishes the
acknowledgement to current consumers, or clears it when the last consumer has
left. Reopened controls refuse a second save until settlement. A later write
preserves the first write's acknowledged preference. Both success and rejection
release the lock, with host values used on a fresh reopening after settlement.

Typecheck passes. The scoped settings/backend run passes all 21 tests, including
the four R1 cases. The complete plugin suite passes all 330 tests in 13 files,
recorded in r1-suite.log. The contract documents the lifetime boundary. This
correction uses the existing SDK and changes only owned settings paths and
WZ11 evidence. Original proof receipts and review history are retained.
